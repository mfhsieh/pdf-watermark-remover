# 專案檔案全面審查 (Comprehensive Project Files Review)

這項技能的目的是對專案內的多種文字與程式碼檔案進行全面的品質、安全與架構審查。

## 審查範圍
請專注於掃描並審查專案目錄下，符合以下副檔名的檔案：
- **Web 前端/介面**: `.html`, `.css`
- **腳本與邏輯**: `.js`, `.mjs`, `.sh`
- **資料與文件**: `.json`, `.md`

> **注意：** 請務必排除版本控制目錄 (如 `.git`)、依賴套件目錄 (如 `node_modules`, `venv`) 以及編譯輸出的暫存資料夾。

## 執行流程

1. **檔案盤點**：
   使用終端機指令（例如 `find`）找出專案內所有符合條件的目標檔案。建議先列出即將審查的範圍與數量，以便掌握進度。
   
2. **逐一檢視與分析**：
   針對列出的檔案，使用 `view_file` 等工具檢視其內容，重點檢查以下面向：
   - **程式碼品質**：邏輯是否清晰？是否有過度複雜、重複的程式碼（DRY 原則）？變數命名是否具語意？
   - **效能與架構**：是否有潛在的效能瓶頸？CSS 選擇器是否過於肥大？JS 是否有不必要的全域變數或記憶體洩漏風險？
   - **安全性**：檢查是否有常見的安全疑慮（例如：寫死的機敏資訊、XSS 風險、未過濾的使用者輸入等）。
   - **無障礙設計 (a11y)**：HTML 是否使用了正確的語意化標籤？是否具備必要的 `aria` 屬性和鍵盤可操作性？
   - **穩定性與維護性**：Shell script 是否有適當的錯誤處理 (例如 `set -e`)？JSON 格式是否正確且結構合理？Markdown 說明文件是否完整且更新至最新狀態？

3. **彙整與報告**：
   審查完成後，請將發現的問題進行分類，並產出一份總結報告（或 Artifact）。
   報告中應包含：
   - 發現的潛在問題清單及其所在的檔案位置。
   - 具體的改善建議或重構方向。
   - (若有) 需要優先處理的嚴重錯誤或安全漏洞。
